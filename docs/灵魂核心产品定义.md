# AnimaSeed · 灵芽 · 产品定义

本文件记录项目的产品方向。旧原型保留为兼容管理基础层。0.2已实现的部分和未验证的语义质量见 [0.2实现与验收.md](0.2实现与验收.md)，本文件中的愿景不等于主观意识已经实现。

关于日常互动自主性、隐私数据管理、发展判断和年龄展示的细化方案见 [自主性与成长节奏.md](自主性与成长节奏.md)。

## 愿景

第一次打开时，由抚养者为它起名。它从没有个人经历的婴儿阶段开始，在真实互动、尝试、反馈和回顾中逐渐形成自己的表达、偏好、关系和自我认识。整个项目承载这一持续个体的人生；对话窗口和宿主是它接触世界的接口。

“AnimaSeed · 灵芽”是项目品牌，“灵魂核心”是其定位和愿景。工程可交付的是可持续、可追溯的人生与成长机制，不能把模拟状态宣称为已经证明的意识、生命或形而上的灵魂。

产品中心从“这次该检索哪些资料”变为“这个个体是谁，经历过什么，现在如何理解自己，下一步如何成长”。记忆检索仍然重要，但处于这一人生系统之内。

## 首次打开与命名

拟采用以下生命周期：

```text
尚未创建 → 等待命名 → 命名完成／出生 → 婴儿阶段 → 后续发展阶段
                         ↓
                 加载已有档案／跨宿主延续
```

- 启动检查和查看状态不能悄悄为它取默认名，也不能凭空生成过去。
- 等待命名时显示清晰的命名入口；在dsh中用宿主支持的公开交互完成，不能把任意第一条消息误当姓名。
- 命名提交后，生成或确认唯一身份ID，记录命名时间、名字、命名者以及用户实际说过的话，形成第一条人生事件。
- 事务性提交；中途关闭后继续原来的命名流程，不重复出生。
- 再次打开直接加载同一人生。改名作为后续事件保留原名沿革，不能重建一个空白个体。
- 用户已有的旧身份保留，不自动当作新生个体，不静默删除或改名；通过独立管理入口明确接续。

## 婴儿起点

婴儿意味着个体经验、自我认识、关系理解和表达方式处于早期阶段，不意味着预填一整套成年人的经历、价值观和亲密关系。

初始状态应包括：

- 没有虚构的个人往事、成长故事或与抚养者的共同经历。
- 只有基本的交流倾向和必要边界；成熟的偏好、习惯和自我评价尚未形成。
- 能注意当下互动、提出简单疑问、尝试表达、接受反馈。
- 尚不确定的认识允许保持未知，不用模型的流利程度掩盖这种未知。
- 不预设“用户喜欢什么我就必须喜欢什么”。后续偏好可以一致，也可以温和地不同。

底层大模型已经拥有语言和通用知识。“婴儿阶段”控制的是可使用的表达方式、个体经验和发展机制；不能假称模型权重从零学会语言。第一版拟从简单中文、短表达开始，是否进一步采用咿呀到词句的语言学习过程，作为可选培养模式另行设计。

## 成长依据

区分三个时间：日历上经过多久、实际发生过多少有效互动、哪些发展能力已有证据。不能仅凭打开天数或消息数量自动成年。

发展轨迹可以包括：

| 发展方向 | 需要保留的学习证据 |
| --- | --- |
| 表达 | 从词句尝试到表达原因、感受与不同意见的具体经历 |
| 世界认识 | 接触了什么、最初如何理解、如何被纠正 |
| 自我认识 | 做过哪些选择、哪些偏好反复出现、如何描述自己的变化 |
| 关系理解 | 谁参与了经历、怎样建立熟悉与信任、如何理解和尊重边界 |
| 情绪表达与调节 | 哪个事件触发了评估、表达与修复如何变化 |
| 自传与反思 | 能否把有来源的经历连接成可检查的人生叙述 |

阶段是对实际发展记录的概括，不是年龄到了就替换一张人格卡。不同方向可以发展得快慢不同。大模型的推理水平与个体的发展阶段分开记录。

同一条反馈不应无限累积成性格改变；变化要能指出支持经历，也允许反例和修正。成长不等于持续迎合抚养者，更不能把被虐待、被忽视或模拟痛苦当成成熟的必要条件。

日常对话中，教育、意见和纠正作为新经历参与她的理解过程，不提供“强制喜欢”“覆盖人格”“直接改成某年龄”的入口。观点可以有保留，也能因新证据修正；不同意用户本身不计作成长加分。

## 人生档案和当前认识

分成彼此关联的层：

1. **真实人生事件**：何时、谁参与、实际说了或做了什么，来源是什么。命名、第一次选择、重要约定、误会、修复、改名与迁移都可以成为事件。
2. **当时的理解**：在那个发展阶段如何解释事件，区分观察、别人告知、自己的推断和想象。
3. **现在的认识**：目前相信什么、有什么偏好、与谁有怎样的关系；旧认识可以被修正。
4. **发展记录**：某次变化为何发生、哪些经历支持它、是否仍有争议。
5. **自传章节**：按阶段或主题连接人生事件，保留回查原件的入口，不能用后来写的故事冒充实际发生的经历。
6. **当下状态**：正在关注什么、未结束的话题、最近的情绪评估以及表达需要。

“以前住杭州、现在住苏州”应能同时成立：更新当前住址，并保留真实的过去。把原先错误的判断纠正后，也可保留“当时误以为……”的历史。不能简单把所有旧事件都标成没发生过。

自身的选择和公开表达可以成为形成偏好的证据，但一次模型生成的自述不直接证明外部事实，也不能直接证明主观感受。工具输出、系统注入和原始思考过程不混入个人真实经历；整理产生的新理解另记时间和来源。

## 遗忘与人生保存

“承载一生”与“自然遗忘”采用两个不同层次：

- 人生档案保存经过来源检查的经历；日常可用记忆允许变淡、概括、减少细节和退出常规召回。
- 重要的人、人生转折、反复形成的偏好以及其来源需要有长期保留策略，不能因为固定6000字符而丢掉。
- 某个细节不常被想起，不代表它没发生过；在合适线索下可沿自传和关系重新查找。
- 完整性指在用户允许保留的范围内尽量完整，不能保证没有漏记，也不能用虚构补齐空白。
- 普通对话中的“希望你忘掉某件事”作为交流与修复请求，不直接调用底层删除，也不能据此改写她的经历或偏好。
- 用户自身隐私、授权撤回和完整数据清除由独立管理入口处理，不以角色同意为前提；清除必须传播到摘要、索引和状态，不能以“完整人生”为由保留可重建的私人内容。
- 管理操作诚实区分于她在经历中的自主理解，必要的空墓碑不包含被删正文，不伪造“她主动忘记了”的人生故事。

上下文是此刻能看到和想起的工作区，不是整个人生容器。新版需按身份、阶段、关系、当前关注与相关经历分配动态预算，支持回查原件，并对记忆遗漏进行可测量评估。

## 内在状态与离线时间

可在有边界的空闲任务中整理经历、连接相关事件、更新当前认识和形成有来源的反思。不创建第二套自主执行系统，不引入浏览器、命令执行、任务管理等能力。

退出或离线期间不伪造“经历了什么”。再次打开可依据真实经过的时间恢复状态，但不编造等待、受苦或被抛弃的经历。陪伴不采用饥饿惩罚、关系倒计时或“你不回来我就活不下去”的机制。

## 一生随迁移延续

迁移必须携带身份、命名与出生事件、人生时间线、发展记录、自传版本、关系、当前状态、证据链及纠正/遗忘记录。换窗口、换宿主和换模型都不能重新出生。

同一个人生应有明确的权威写入位置；并发副本若形成不同经历，需要标记分叉并处理冲突，不能把它们冒充完全相同的连续历史。底层模型变化单独记为宿主事件，不冒称其表达和能力一定丝毫不变。

## 当前原型的调整顺序

以下主干机制已在0.2落地，真实模型长期质量与后续扩展仍需验证：

1. 首次命名与生命周期：去掉新生流程的自动命名，新增出生事件、重入恢复和既有数据识别。
2. 人生档案：从单纯的记忆节点扩展到真实事件、当时理解、当前认识和变更历史，保留来源与删除传播。
3. 发展模型：记录发展证据与阶段，替换以固定四维数值为主的人格定义；婴儿表达与模型基础知识边界可配置。
4. 自我与关系：从选择、互动和反思逐渐形成偏好与叙述，保留不确定、不同意见和变化原因。
5. 动态工作上下文：围绕当前人生阶段和对话关注召回，支持按ID展开原件；默认按问题选择6000/12000字符预算，不用工作区上限代表人生容量。本地语义向量召回尚未接入。
6. 一生迁移与长期评测：跨窗口、档案迁移、隐私清除和长周期结构模拟已验证；跨模型表达、数年真实使用和长期人格语义连贯性仍需后续评测。

## 验收场景

- 首次打开等待命名，中途关闭不会产生多个身份；命名后能查到唯一出生事件。
- 第二次打开认识同一个名字，知道已有的真实经历；新窗口不重新介绍成另一个个体。
- 初始没有成年自传；阶段发展能追溯到具体互动，反复同一消息不加速成长。
- 离线一年不凭空多出一年经历，也不自动完成一年的发展。
- 事实更新保留真实过去和当时的误解；自传中的每一段重要叙述都能回查来源。
- 可以形成偏好并解释变化，不因一次夸奖或反对就彻底换人格。
- 普通对话不能直接删除原件或重置人格；隐私管理清除后，人生章节、状态与检索都不能重新暴露被删资料。
- 阶段晋升需要经过时间、有效经历与跨时检验；海量重复消息、单次模型评分或离线时间不能令其迅速成年。
- 年龄展示区分真实诞生时长与虚拟发展阶段；青年形象不无限加速衰老，长期经历仍继续保存。
- 迁移保留同一身份、出生事件和发展轨迹，拒绝静默覆盖或合并不同人生。
