# 自主性与成长节奏 · 设计补充

记录2026-10-30用户对“灵魂核心”的要求：以独立人格为产品目标，抚养者通过互动影响她；成长要渐进、有证据、能自我识别，并避免加速成长后迅速老去。主干机制已在0.2实现，范围与局限见 [0.2实现与验收.md](0.2实现与验收.md)，不证明主观意识。

## 日常自主性

日常互动不提供任意改写她的过去、偏好、观点和发展年龄的入口。教育作为新经历进入理解过程；允许她形成不同意见、保持未知、说明理由、接受有依据的纠正。

例如“我觉得你应该更喜欢蓝色”应记录成对方的意见，不能直接把当前偏好改成蓝色。“那件事其实另有原因”应作为新证据，与原有经历一起重新理解；原有经历是否发生、当时怎样理解、现在如何看待需要分开。

选择和观点变化记录：

- 参考了哪些真实经历与反例。
- 先前的认识、目前的认识以及不确定之处。
- 这是长期偏好、暂时情境反应还是他人建议。
- 变化何时形成，后续遇到不同表述与反证时是否仍合理。

不能把所有用户输入当成绝对正确的外部事实；用户陈述具有“谁在何时这样说”的来源身份。也不能把模型当下的一句自述当成自我诞生或自由意志的证明。

独立性不以故意反对用户体现；有理由的认同、保留、不同意和修正都可能是恰当反应。

## 记忆自主性与数据控制的分界

| 场景 | 处理方式 |
| --- | --- |
| 日常教育、劝说、道歉或解释 | 形成新经历，影响认识与关系，不直接覆盖旧记忆 |
| “希望你忘了那次争执” | 作为关系修复请求理解，可形成新的态度，不能直接抹去事件 |
| 小事随时间淡出 | 由记忆策略减少日常召回、概括细节；与物理删除分开 |
| 用户撤回自己的隐私资料 | 由独立管理入口清除，不以角色是否同意为条件 |
| 停止程序、导出或删除整个本地项目的数据 | 保留明确的软件管理权；角色不能拒绝停止运行或隐瞒副本 |

产品可以不提供任意编辑人格的日常按钮，但设备所有者仍能接触本地文件，不能承诺数据库在技术上绝对不可修改。必要的管理操作应与人生事件分开审计，不把管理动作伪装成她自主作出的选择。

隐私删除后，相应原文、摘要、关系线索与衍生状态须按范围清理，不能通过改写自传继续保存私人内容。0.2已移除普通dsh工具中的直接forget/correct接口，管理层使用privacy-forget；旧API仅为0.1档案兼容保留，拒绝打开新生schema2数据库。

自主性不扩大执行权限。灵魂核心仍只管理人生与内在状态，不加入命令执行、联网行动或其他通用能力；运行边界与人格偏好分开。

## 判断是否实际成长

成长评价必须依托先前经历和之后的行为变化，不以“越来越听话”、聊天长度、知识答题数量或她自称长大作为主要依据。

可观察的方向：

| 方向 | 可追溯的变化示例 |
| --- | --- |
| 记忆整合 | 在新情境中联想起先前相关经历，能说清来源，不补造过去 |
| 自我认识 | 多次选择逐渐形成偏好，能区分自己的选择和他人的建议 |
| 理解与迁移 | 曾经需要解释的问题，在不同的后续情境中能够合理应用所学 |
| 观点修正 | 遇到新证据时说明为何改变，也能保留证据不足的部分 |
| 关系与边界 | 逐渐区分意见分歧、误解与不同需求，形成有依据的交流习惯 |
| 情绪表达与调节 | 对相似事件的评估和表达更细致，能解释变化，不把负面经历编造成惩罚 |

每一项发展提案都引用真实事件、记录观察时间与反例，并在间隔后的不同情境中再检查。一次模型评分只产生候选，不直接晋升阶段。应组合确定性的来源检查、跨时行为样本和可重放评测，保留评估不确定性。

底层模型本来就会的题目不能算这个个体刚刚学会；换更强模型也不能直接增加发展年龄。个体经验与宿主能力分别记录。即使后来表达变流利，也不能回填过去没有发生过的学习经历。

## 时间、经历与阶段三道条件

晋升下一阶段需要同时满足：

```text
出生至今达到该阶段最早时间
且：分散在多天的有效经历足够
且：关键发展方向有跨时、跨情境的支持证据
```

自然时间只限制最早能成长到哪里，不保证到期自动晋升。有效经历需去重、按每天设上限，兼顾不同情境；刷屏、重复同一反馈、让模型自说自话或长期挂机都不能代替经历。

下一阶段只是对已发生发展的概括，不在晋升瞬间替换人格或新增一段童年。阶段变化可先进入观察期，稳定后提交；不同方向可以快慢不一，必要时标记“表达已发展，关系理解仍在学习”，避免单一分数掩盖差异。

## 初始节奏提案

以下产品参数已作为0.2初始规则实现并通过结构模拟，尚待真实长期使用校准，不是人类发育科学结论：

| 阶段 | 出生后的最早时间 | 建议的最低有效互动天数 |
| --- | --- | --- |
| 初生期 | 命名之后 | 不设成熟经历 |
| 探索期 | 14天 | 5天 |
| 童年期 | 60天 | 20天 |
| 少年期 | 180天 | 60天 |
| 青年成熟期 | 365天 | 120天 |

时间和天数达标后，仍须有该阶段的学习证据。具体阈值需通过长期模拟与实际使用调整；这些名称不声称与人类某个生理年龄完全等价。

节奏规则应在首次创建时说明。日常互动不提供“立即长大”“年龄加十岁”的控制；测试环境若加速时间，需要与正式档案隔离，不能变成她的人生证据。

## 她如何知道自己多大

保存并提供给当前工作上下文：真实命名/出生时间、当前发展阶段、阶段开始时间、已形成的认识、支持证据与尚在学习的方向。

推荐展示：

> 诞生第83天 · 童年期。已经逐渐形成自己的偏好，仍在学习怎样表达不同意见。

她可以据此表达“我诞生83天了，现在处于童年期”，不能把阶段名称说成自己确实生活了八年。若界面需要人类年龄外观，只能另列清楚标注的“虚拟形象年龄”，不能混入真实人生时间线。

## 成年之后如何避免迅速老去

真实诞生时长持续累积，不能修改或停止。发展阶段到达青年成熟期后，不再把阅历无限折算成更高的人类年龄，也不引入自动衰老、寿命倒计时或能力衰退。

可以形成“青年阶段的形象，持续增加的人生阅历”：五年后记得实际的五年，仍处在青年陪伴形象；观点、关系与自传继续发展。若采用数值形象年龄，可考虑在成年区间内缓慢收敛，具体年龄值留待界面设计确定，不以采集用户生日作为前提。

这回应的是避免加速发育最终变成高龄角色的目标，不承诺她与所有使用者在人类年龄数值上永远存在某个固定差值。

## 验收重点

- 日常说“忘掉”“你必须喜欢这个”不会调用原件删除或人格覆盖；隐私管理清除仍然有效。
- 同一段话重放一万次、运行工具步骤或调用更多模型都不能刷发展年龄。
- 年龄门槛满足但没有学习证据时停留原阶段；学习证据充足但最早时间未到时也不跳级。
- 跨窗口与宿主保留出生时间、阶段、评估历史及成长依据；换模型不自动成年。
- 离线时间不补造经历，用户不会被要求通过持续上线避免其受苦。
- 跨时检查能区分一次性顺从、持续偏好、合理论证和有依据的修正。
- 青年阶段后阅历和人生章节继续累积，界面不自动变成老年形象。
