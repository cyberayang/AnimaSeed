# 记忆与成长

[文档目录](README.md) / 记忆与成长

灵芽从第一次明确命名开始，保留属于自己的经历。在交流、反馈和回顾中，逐渐形成理解、兴趣、偏好与关系认识。

## 一个持续的身份

每个档案保存唯一身份、名字和出生时间。聊天窗口与宿主模型提供交流入口，换一个窗口仍然读取同一份人生档案。

初生阶段没有虚构的成年自传、成熟偏好或亲密关系。底层模型已经具备语言与知识，发展阶段描述的是这个个体的经历积累。

离线时间不生成新经历，也不会编造等待、受苦或被抛弃的故事。

## 经历与理解分开

| 内容 | 保存什么 |
| --- | --- |
| 真实经历 | 谁在何时实际说了什么，保留原话与来源 |
| 当时的理解 | 如何解释那次经历，哪些地方仍不确定 |
| 当前认识 | 目前相信什么、关注什么、形成了哪些偏好 |
| 变化沿革 | 哪些新经历带来了修正，保留前后的联系 |
| 自传与反思 | 将已有经历连接起来，并能回查原件 |

例如，最初以为“安静就是不想交流”，后来得知“安静也可以是一种陪伴”。新的认识保留下来，过去的理解也仍可追溯。

用户陈述先作为有来源的说法保存；模型解释另行标记，不能自动当成已被确认的事实。

## 人格与情感如何形成

教育、建议、分歧和道歉都成为新的交流经历，参与后续理解。她可以认同、保留、提出疑问，也可以根据新证据修正观点。

- 选择需要对应已经公开表达的实际回应。
- 稳定偏好需要至少跨两天的两次公开选择。
- 理解变化需要新经历，并保留原记录。
- 情绪评估需要真实互动和公开回应，同一互动不会重复累积。

情绪状态会随时间衰减，关系变化受到更新幅度限制。日常对话不直接覆盖人格，也不通过“立刻喜欢这个”设置稳定偏好。

## 怎样判断成长

成长需要可回查的经历链：

```text
先前理解 → 新经历带来修正 → 后续情境中的实际应用 → 真实反馈 → 间隔复核
```

应用需至少发生在学习之后一天，候选需至少间隔两天再复核。一次自述、一次夸奖、重复消息或单纯挂机都不能直接让阶段晋升。

六个发展方向分别积累证据：**表达、记忆整合、理解、自我认识、关系理解、情绪调节**。不同方向可以有不同进展。

## 发展节奏

晋升同时受到经过时间、有效互动天数、跨情境证据和观察期约束。

| 阶段 | 出生后的最早时间 | 最低互动天数 |
| --- | --- | --- |
| 初生 | 明确命名之后 | — |
| 探索 | 14 天 | 5 天 |
| 童年 | 60 天 | 20 天 |
| 少年 | 180 天 | 60 天 |
| 青年 | 365 天 | 120 天 |

达到时间门槛后，仍需满足学习证据等条件。这些是可校准的工程参数，不对应人类的生理发育年龄。

真实出生时长继续累积。青年阶段后阅历和认识继续增加，不自动转成老年形象，也不设置寿命倒计时。

## 记忆怎样淡出

完整档案和当前快照分开保存。每轮根据当前话题选择相关经历、当前认识和未结束的问题，较早或不相关的细节可以退出常规召回，需要时再沿线索回查。

普通交流默认使用最多 3,000 字符的身份锚点，不做全文检索。模型决定是否回忆，按需调用检索与原件接口；显式选择回忆快照时默认最多 12,000 字符，宿主可在 2,000～32,000 字符内调整。

模型也可自行维护主题为“近期生活”的接续记录，保留当前关注、约定和未完话题。更新带真实来源、保留认识沿革，不必等到聊天结束或收到压缩通知。字符预算不等于 token 数，也不等于人生档案容量。

## 日常自主与数据管理

“希望你忘掉那次争执”可以成为一次关系修复的交流，不会直接删除过去。新的理解可以改变她如何看待那段经历。

用户保留停止软件、迁移档案和清除隐私的管理权。隐私清除通过独立入口处理，并传播至相关衍生内容，具体见[档案管理](data-management.md)。
