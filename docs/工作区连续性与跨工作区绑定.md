# 工作区连续性与跨工作区绑定

这是用户收拢核心边界后的产品约束。灵魂核心负责持续身份、人生档案、记忆读写与首次引导；宿主接入、模型调用和形象绑定由接入者解决。现有dsh插件可作为参考，完整桌宠桥接不再是核心的前置条件。

## 跨对话连续性优先

默认一个工作区使用一个灵魂档案。宿主每次开始对话先执行工作区引导：检查命名状态、读取同一个soulId与当前有效状态、召回相关经历和未结束话题；消息提交后保存实际经历；整理通过宿主已有模型完成。

人生档案独立于聊天窗口。关闭窗口、更换会话或整理工作上下文都不重新创建身份。模型的单次输入仍然有容量限制，因此长期连续性需要依赖档案、检索、压缩、来源回查和状态接续，不能声称让模型无限读取全部人生。

单工作区闭环已经补齐：workspace-init安装引导并固定身份，workspace-open恢复当前状态，receive/reply保存真实交流，record保留有来源的认识与未完话题。详见[工作区闭环使用](工作区闭环使用.md)。根AGENTS保留维护约束，只对日常陪伴启用引导，不把维护者对话自动冒充新生个体的经历。

以下扩展由每位使用者自行决定是否实施，**不再列为核心闭环的必做事项**。核心不自动共享、联网同步或绑定形象。

## 自选扩展清单

| 扩展 | 什么时候考虑 | 当前状态与需自行解决的问题 |
| --- | --- | --- |
| 多工作区接续同一灵魂 | 希望她参与不同项目 | SDK显式dataDir可复用；工作区命令目前仅固定本地data/soul，尚无外部绑定入口 |
| 跨设备迁移 | 换电脑，先后使用 | 现有加密导出/导入可用，停止旧端写入后迁移；新工作区需自行接续正确档案 |
| 离线多端自动同步 | 多台设备同时积累经历 | 未实现；需事件协议、身份校验、冲突处理与隐私删除传播 |
| 细分工作区资料范围 | 希望人格连续但项目资料有边界 | 未实现读取权限；来源、共享范围与衍生摘要要一起约束 |
| 语义检索增强 | 经常用不同措辞回忆同一件事 | 目前中英文全文检索；向量模型、索引、成本与重建由接入者选择 |
| 宿主自动整理 | 希望减少手动调用record | SDK有界反思与dsh参考适配已支持；其他宿主自行接生命周期、取消和预算，核心不内置模型 |
| 形象、语音和其他智能体接入 | 希望她有不同呈现和能力 | 接入者负责，参考接入文档；不改变权威人生身份，不把界面人格另存成第二个人 |

每项都可以暂时不做。选择扩展时仍须保留核心的真实来源、唯一身份、隐私撤回和不伪造经历等约束；这些不是可选项。

## 跨工作区延续的三种情况

| 情况 | 初始方案 |
| --- | --- |
| 同一电脑，多个工作区接续同一灵魂 | 由用户显式绑定同一权威人生目录，不复制多份数据库 |
| 不同电脑，先后使用同一灵魂 | 先停止旧端写入，再加密导出/导入，保持身份ID；当前已有迁移机制 |
| 不同灵魂或不希望共享资料的工作区 | 继续独立，不按名字相同而合并，不默认全局共享 |

绑定是选择“使用哪一份人生”，不是让两份各自修改过的人生自动合并。目录搬迁也应依据soulId验证身份，不能只依据文件夹名或显示名字。

## 绑定与资料范围

一个工作区的默认身份入口可以通过显式选择，接续已有的同一灵魂。不同工作区通常仍有各自的当前话题、文档、任务背景和权限；这些上下文不因身份相同就变成全局指令。

0.2同一dataDir意味着共享整份可信档案，当前没有按工作区隔离读取权限。初版绑定必须明确说明这一点，不能承诺只共享人格而自动隔离所有项目秘密。细粒度范围管理可后续增加来源工作区和共享标记，并让衍生内容继承范围约束。

私有人生、绑定路径、密钥和宿主配置不随GitHub模板发布。别人克隆核心模板后应创建自己的独立档案；接续已有档案需要明确选择。

## 第一版暂不做自动双向同步

同一灵魂的两个副本可能产生不同的经历、解释与成长判断；按文件修改时间覆盖可能丢失真实经历。隐私删除在旧副本上线后也不能被复活。

当前导入会拒绝覆盖已有档案，不能把它当成合并命令。跨机器也不让多个进程直接通过网络共享文件读写SQLite。官方说明指出，网络文件系统的同步和锁定可靠性可能与本地不同：[SQLite网络使用说明](https://sqlite.org/useovernet.html)。

若以后需要离线多端同步，应同步有唯一ID的人生事件、理解变更、来源与删除墓碑；发生冲突时保留可检查的分歧，重新计算派生状态。不能把两端年龄、情绪或成长分数直接相加，不覆盖出生身份，也不让旧事件重新恢复已清除资料。

这属于后续的档案协议能力，传输与云端服务可以继续交给宿主或外部工具。核心不因此承担云账号、模型供应商或设备管理。

## 核心验收边界

当前只验收单工作区：首次引导、唯一出生身份、真实消息读写、原件回查、未结束话题和理解沿革、新对话接续、失败不悄悄换人。跨工作区绑定、同步服务与前端桥接不计入本轮完成条件，也不因为此方案存在就自动开始实施。
